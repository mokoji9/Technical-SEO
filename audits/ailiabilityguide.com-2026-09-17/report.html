Critical Crawlability Moderate Now confirmed

Cloudflare is blocking Googlebot, breaking real page resources — and it's intermittent

Google Search Console shows 16 pages blocked with a 403, sourced directly from Google's own crawl attempts. Separately, DataForSEO's Lighthouse run — a real headless-Chrome render, not a UA spoof — logged three resource requests failing with 403 during the page's own load. Re-tested independently later the same day: the same curl request repeated a few seconds apart returned a mix of 200 and 403 — the block is probabilistic, not absolute.

Search Console → Indexing → Pages → Why pages aren't indexed
→ Blocked due to access forbidden (403) · Source: Website · 16 pages
Lighthouse render, console errors (this run)
→ 403 on .../navigation/view.min.js, .../image-lazy-loader.min.js, .../cardo_normal_400.woff2
curl (browser UA) x3, a few seconds apart
→ 200, 403, 403

This is more direct evidence of active harm than a bot-only challenge page — it's why Lighthouse's Best Practices score is still 77 today. The intermittency is exactly why a quick manual check can look fine while Google's crawl still gets caught often enough to matter.

How to fix it, step by step Cloudflare dashboard
  1. Open Security → Bots and confirm Verified Bots is set to allow.
  2. Check Security → Settings for "I'm Under Attack Mode" — should be off outside an active attack.
  3. Review Security → WAF → Custom Rules for anything blocking by missing cookie, missing JS execution, or ASN/IP range — this is likely also what's catching the JS/font sub-resource requests.
Done when: the "Blocked (403)" count in GSC trends toward zero, and a fresh Lighthouse run shows no 403s in its console-error log.

16 pages held up by only one internal link, and the crawl hits max depth

Ahrefs flags "Page has only one dofollow incoming internal link" on 16 indexable pages (9 more non-indexable), plus its own banner that the site "may not be fully crawled" because pages sit considerably distant from the seed.

Ahrefs Site Audit → Links → "Page has only one dofollow incoming internal link"

How to fix it, step by step CMS content / navigation
  1. Export the flagged URLs from Ahrefs.
  2. Add each to a second real navigation path — a topic-hub page, a "related articles" module, or cross-links from closely related posts.
  3. Reduce click depth where a category/hub page could link directly instead of relying on pagination alone.
Done when: the "only one incoming link" count drops, and GSC's "Discovered/Crawled – not indexed" counts trend down.

Recommended order of attack

  1. Fix the Cloudflare rule and link in the 16 weakly-linked pages — both moderate effort, together the biggest lever on the 171-page indexing gap.
  2. Let Google re-crawl and re-check GSC's indexing breakdown — confirms whether #1 actually moves the needle.
  3. Fix meta description, title, and focus keyphrase together per page — one editing pass is more efficient than three separate ones.
  4. Add security headers — quick win, no code deploy.
  5. FAQ schema, Open Graph tags, minor link cleanups, favicon — all quick-to-moderate.
  6. Editorial call on content complexity, and the GSC/Ahrefs noindex discrepancy — lower urgency.
Note: this audit and the parallel driverinsurancehub.com follow-up (run through the same workflow) both found 100% of pages/posts missing a Yoast Focus Keyphrase — if these sites share an operator or template setup, that's worth addressing as one process fix rather than two separate ones.
